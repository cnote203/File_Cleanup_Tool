# Plan format

`apply` and `explore --plan` read a CSV in either of two layouts. Column names are case-insensitive and a
UTF-8 byte-order mark (what Excel writes) is fine.

## 1. The explorer's action plan

Written by **Export action plan (CSV)** in the explorer. One row per file or folder.

| Column | Meaning |
|---|---|
| `path` | Path relative to the scanned folder, backslash separated. |
| `type` | `file` or `folder`. Folder rows are ignored by `apply`; their decision is already on each file inside. |
| `action` | `keep`, `archive`, `delete`, `move`, `discuss` or `undecided`. |
| `new_path` | Where the file lands, for `move` and `archive`. Empty for `keep`. |
| other columns | `size_kb`, `modified`, `source`, `reviewers`, `notes`: informational. |

A Move decision on a folder uses the **New parent folder** box: the folder goes *inside* it. Moving `Reports`
to `Reports\2025` gives `Reports\2025\Reports\...`.

## 2. A mapping sheet

Hand-built in Excel, produced by `suggest`, or generated by your own script.

| Column | Meaning |
|---|---|
| `old_path` | Path relative to the source folder. |
| `new_path` | Path relative to the destination folder, including the file name. |
| `action` | `Move`, `Archive`, `Keep`; anything else (for example `Duplicate - ignored`) is left out. |

`suggest` also writes `rule` (which rule decided), `size_kb` and `modified`.

## What gets copied

| Action | Copied | Destination |
|---|---|---|
| move | yes | `new_path` |
| archive | yes | `new_path` (the explorer uses `Archive\<old path>`) |
| keep | yes | `new_path`, or the old path if empty |
| delete, discuss, duplicate | no | |
| undecided | only with `--undecided keep` | the old path |
